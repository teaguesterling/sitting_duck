## Shape A is larger than #288's example

#288 shows bare parameters and for-loop targets. Measured, one 22-line Python
file has ten such names, across five binding constructs:

```
identifier         x            <- bare parameter
identifier         zz           <- for-loop target
as_pattern_target  handle       <- with ... as
as_pattern_target  e            <- except ... as
identifier         a, b         <- tuple assignment targets
identifier         self, conn   <- bare parameters
attribute          self.cache   <- dotted tuple target
attribute          self.size    <- dotted tuple target
```

All ten have `is_name_definition(flags)` true and `is_definition(semantic_type)`
false, so all ten are absent from `ast_definitions()`. The construct list is the
same list #64 calls "likely missing", which is why #64 closes as superseded.

## Drift from the issue text

1. **#273's mechanism is narrower than reported.** The right-hand side leaks
   into `name` only when the first child after a non-identifier target is a bare
   identifier.

   | source | reported name |
   |---|---|
   | `self.db = conn` | `conn` — the RHS |
   | `obj.attr = 5` | empty |
   | `arr[0] = 6` | empty |

   So this is `FIND_IDENTIFIER` scanning past the target into the RHS, not a
   general "name comes from the RHS" rule. A fix that stops the scan at the
   target closes all three rows at once.

2. **#140a has got worse, and the issue's number no longer holds.** The issue
   records 22 of 95 `command` nodes named. Measured today it is **0 of 95**.
   `command_name` exists, 95 of them, and is also unnamed. The command word is
   present and named on `word` nodes, 161 of them. So the target is
   `command_name`'s `word` child, and the 22 in the issue text should not be
   used as a baseline. **Conflict resolved, by reading the commit that caused
   it.** It regressed after the issue was filed, and deliberately. Commit
   `28c61fd` ("#139 IS_CONSTITUENT", 2026-09-14) changed `command` from
   `EXECUTION_STATEMENT, FIND_IDENTIFIER` to `COMPUTATION_CALL, NONE`, and its
   message says why: "Left UNNAMED deliberately: correct command-name binding
   needs machinery tracked in #140; naming it wrongly (FIND_IDENTIFIER picked
   `+%s`) would defeat the #89 'can't answer -> raise, never silent empty'
   guard." So the issue's 22 were NAMED BUT WRONG, not a different set --
   `+%s` is an argument of `date +%s` in test/data/call_extraction/calls.sh,
   because argument words are direct children of `command` while the command
   name sits inside a `command_name` wrapper. #140a is therefore not a
   FIND_IDENTIFIER repair; it is the binding that commit deferred.

3. **#140b: neither Go node is usable on its own.** `type_spec` carries the name
   `Point` but has no role flag and no definition semantic type.
   `struct_type` has a definition semantic type but an empty name. The fix must
   join them, and choosing either node alone leaves the other half missing.

4. **#277's name is an empty string, not NULL.** The issue says `<NULL>`. The
   macro filters `name IS NOT NULL AND name != ''`, so it drops either way, but
   a test asserting NULL would be wrong.

5. **#283's pointered form does not parse into a function.** Three of four
   `function_definition` rows come back for four functions.
   `pointered(Args*... args)` produces no row at all, so it is not a parameter
   defect there — the function itself is invisible. That makes it the most
   serious of the three qualified forms, and possibly a separate defect.

6. **Go `a, b := 2, 3` is one node binding two names.** Both
   `short_var_declaration` rows carry an empty name. Same shape as JS
   `let a = 1, b = 2`, where the container claims only `a`. A single-valued
   `name` column cannot express either, so the release has to state what it does
   rather than pick one name.

### The mirror file is coupled by design, not by grep

## #140b, as landed — and the two oracles it corrected

Landed as `b20ef61` (test, verified red), `527f008` (the oracle corrections)
and `3554016` (the fix).

**The generality question Teague set, answered.** His condition was "make sure
it's reasonably general beyond just Go. If it's useful and general we can add it
as a flag." Measured, the condition does not apply: **`IS_CONSTITUENT` already
exists**, added by `28c61fd` for #139, and it is already set on 50 node types
across 17 languages. Nothing is minted. Applying it to two more node types is
configuration, not a taxonomy change.

The shape itself is NOT general. A survey of every node with a `DEFINITION_*`
semantic type, `name_strategy='none'`, not syntax-only and not already a
constituent returns about 51 rows, and they fall into three groups:

| group | count | is it "an unnamed body duplicating its named declaration"? |
|---|---|---|
| root / file nodes (`program`, `source_file`, `module`, …) | ~25 | No. Top-level construct. This is #186's subject. |
| genuinely anonymous constructs (kotlin lambdas and initializers, typescript call/construct/index signatures, cpp `default_method_clause`, java `static_initializer`, graphql schema nodes) | ~24 | No. They duplicate no named parent. |
| **go `struct_type`, `interface_type`** | **2** | **Yes.** |

And the fallback Teague named is unavailable: the `Class` refinement is 2 bits
and `REGULAR`, `ABSTRACT`, `GENERIC`, `ENUM` are all assigned
(`src/include/node_config.hpp:242-247`).

**The cost, on the record.** Every one of the 50 existing constituents is
context-FREE: a string's content is always a sub-part. Go's `struct_type` is
context-DEPENDENT — a sub-part in `type Pair struct{}`, the whole construct in
`var anonymous struct{}` and in `struct{}{}`, which is how Go spells a set
element. A stored per-node-type bit cannot express that, and `28c61fd`
deliberately chose a stored bit over a structural query. So the two anonymous
forms leave `.class`. Section 4 of the test pins the loss.

**Measured before and after**, over every committed Go fixture:

| | before | after |
|---|---|---|
| `ast_definitions()` class rows for Go | **0** | **11** |
| `.class` rows over the #140b fixture | 4, all with an empty name | 7, all named |
| `ast_resolve_entity('Read').qualified_name` | `F[Read]` | `C[Reader] F[Read]` |

### Two oracles I put on record and had to correct

1. **The flag byte reads 30, not 14.** `30 = IS_EXPORTED (16) | IS_SCOPE (8) |
   NAME_DEFINITION (6)`. The exported bit comes from Go's capitalization rule at
   parse time, not from the `.def` entry, and every name in the first fixture
   was capitalized, so the bit was invisible to the prediction. `type
   unexported int` is now the control: 14 against its siblings' 30.

2. **The body must not keep `IS_SCOPE`.** With the flag on both nodes, Go had
   two stacked class scopes, and `scope.class` for the field `First` pointed at
   the unnamed `struct_type` while `.class#Pair` matched the `type_spec`:

   ```
   .variable:in-scope(.class#Pair)   -> EMPTY
   .class#Pair .variable             -> First, Second
   ```

   Two forms of one question disagreeing is #166's defect. No other language
   gives a type BODY a scope — java `class_body`, typescript `interface_body`,
   rust `field_declaration_list` are all flags 0 — so removing it matches the
   house convention. The only measured loss is that an anonymous struct's field
   reports `scope.class = NULL` instead of an unnamed node id. Its
   `qualified_name` is unchanged.

**Generated artifacts.** A `.def` change needs
`python3 docs/scripts/generate_language_reference.py` committed with it, and
`scripts/check_def_type_tables.py` run first. Note the generator FLATTENS every
`* ` line between `@defgroup` and `@{` into one paragraph
(`generate_language_reference.py:113-119`), so a long rationale belongs in a
plain `//` block above the doxygen comment, not inside it.
