# Sitting Duck v1.18.0

**Release date:** 2026-11-04

DuckDB 2.0, and a declaration surface that can finally be asked what it promised.

**This release requires DuckDB 2.0.** The `duckdb` submodule pin moved from
`069cc9f9` (the v1.5.6 line) to `d54cbbe3` (v2.0.0), and the v1.5 build leg was
removed with it. An extension built against DuckDB 1.5 and one built against
2.0 cannot co-load, because the ABI is exact-version, so this is a hard
requirement rather than a recommendation.

Two things changed shape for callers: `ast_type_map()` gained a column in the
middle of its schema, and four native-extraction paths that returned populated
but wrong values now return correct ones. v1.17.0's notes said "no API changed
shape". This release cannot say that.

## New

**`ast_type_map()` reports `native_strategy`** (#042). Every `DEF_TYPE` entry
declares two extraction strategies. Only the first was readable from SQL, so
the second — the one that decides whether a node gets parameters, a signature
or a return type — could be read only by opening `languages/*/*_types.def` with
a text scanner.

That mattered because a basename-based source scan cannot see a table the
preprocessor assembles. `languages/typescript/typescript_types.def:60` is an
`#include` of javascript's table, so a scan attributing rows by filename found
**5** function-shaped declarations where the loaded map holds **13**, 11 of them
`FUNCTION_WITH_PARAMS`. The column reports the loaded map, so it answers for a
module whose table is assembled at compile time, and for one that ships no
sources at all.

```sql
-- Which node types declare that they deliver parameters?
SELECT language, node_type, native_strategy
FROM ast_type_map()
WHERE native_strategy = 'function_with_params'
ORDER BY language, node_type;
```

Measured on this candidate: **77** rows.

**The conformance kit judges each declaring node type** (#042, #259). The kit's
`NATIVE-DECL` check previously asked one question per language. It now asks one
per `(node_type, native_strategy)` pair read from `ast_type_map()`, so a
language that delivers for `function_definition` can no longer cover for the
same language declaring and not delivering on `method_definition`.

`NATIVE-DECL` also gained the negative control it never had. The check had a
matrix column and no planted fault, so nothing proved it could fail. It now
plants a declaration nothing can serve, and a second control asserts the
staleness message rather than only the verdict.

14 pairs that declare a strategy and deliver nothing are recorded in
`spec/conformance/native-decl-baseline.tsv`, each with its measurement and the
reason. The contract is bidirectional: a baselined pair that starts delivering
fails the gate too, so the file cannot quietly outlive the defect it describes.

## Output changes

**`ast_type_map()`'s schema grew from 9 columns to 10, and `flags` moved.**
`native_strategy` was inserted at index 8, beside `name_strategy`, because the
two strategies are the third and fourth arguments of `DEF_TYPE` and belong
together. `flags` moved from index 8 to index 9.

| | v1.17.0 | v1.18.0 |
|---|---|---|
| index 7 | `name_strategy` | `name_strategy` |
| index 8 | `flags` | **`native_strategy`** |
| index 9 | — | `flags` |

A query that names its columns is unaffected. A query that reads `flags` by
position now reads `native_strategy`. Appending the column after `flags` would
have kept positional callers working, and would also have put the fourth
argument of `DEF_TYPE` after the fifth.

Measured, not assumed: no positional caller was found in this repository or in
the sibling repositories under `~/Projects`. Every use reads `language`,
`node_type` or `kind` by name.

**Python annotated assignments report the annotation.** `d: float = 1`
reported `int`, inferred from the right-hand side, because the annotation was
never consulted. It now reports `float`.

**Python stops reporting its own node type as a type.** `y: int` reported
`assignment` — the name of the node being described. The leak was in two
places, not one: the `assignment` node itself and the four annotation
`identifier` nodes under it. Five nodes per annotated statement, measured; both
paths are fixed.

**Swift call arguments are arguments.** `add(a: 1, b: 2)` delivered one
argument whose text was `(a: 1, b: 2)`. It now delivers two, `a: 1` and `b: 2`.

**Lua `local` declarations are not exported.** `local l_local = 2` and
`local function l_func() end` both reported as exported. They now report
`is_exported(flags) = false`.

**Lua modifiers stop at the declaration.** A nested anonymous function
inherited `local` from an enclosing declaration, so a function with no modifier
reported one. A directly declared `local function` keeps its `local`.

## Fixes

Each of the four native-extraction fixes above had a test written and verified
red before the implementation changed, in its own commit. The four bug tests
are `test/sql/bugs/042_python_type_annotations.test`,
`042_swift_call_arguments.test`, `042_lua_modifier_scope.test` and
`042_lua_local_visibility.test`.

**The swift fix was a nesting level, not a renamed literal.** The grammar emits
`value_arguments`, not `argument_list`, but `value_arguments` is a *grandchild*
of the call node and the matcher only inspects direct children. Renaming the
literal alone would have delivered zero arguments instead of one wrong one. The
matcher now descends one level through the wrapper.

**The lua visibility fix reads a keyword, not a node type.**
`LuaAdapter::IsPublicNode` tested for `local_function` and
`local_variable_declaration`. tree-sitter-lua emits neither, so both branches
were unreachable and every declaration came back public. `local` is a direct
child of the declaration node, and that is what the check now reads.

**`functions.md` documented a schema `ast_type_map()` never had.** Its Output
Schema listed seven columns, three of which did not exist (`semantic_name`,
`selector`, `strategy`), and two of its three examples could not run. The real
ten columns are now documented, and a stale `WHERE selector = '.func'` example
in `src/ast_type_map_function.cpp` was replaced with one that runs.

## Internal

**Per-language sources moved to `languages/<lang>/`** (#054, M2 stages 0–2).
88 files were relocated in one commit that is a pure rename — 88 files, 0
insertions, 0 deletions — so that a later history rewrite can follow them.
Each language now owns a `module.cmake`, and the two CMake parsers follow the
includer rather than a glob.

**The `DEF_TYPE` duplicate-raw-type gate** (#047) checks 3837 entries across 31
translation-unit roots, reading the preprocessor's view rather than a file's.

**The native-dispatch gate widened from one check to three.** Its literal count
roughly doubled as a result, from 765 to 1380, so its dead-literal count is not
comparable to v1.17.0's: v1.17.0 reported 26 dead of 765 under the narrow
check, and this release reports **69 dead of 1380** under three. The gate now
exits 0 against a recorded baseline rather than exiting non-zero by design.

One of those 69 moved during this cycle, in the direction people forget to
check. The swift fix made `argument_list` *absent* rather than dead, and a
bidirectional baseline fails on that too, so `spec/abi/module-abi.yaml` lost
one line and the count went from 70 to 69. A baseline that only catches
regressions would have stayed silently wrong.

## Known issues

**`ast_select` is slow on DuckDB 2.0** (#040). Re-measured against the v2.0.0
tag: 13.05 s to execute and 72.23 s to `EXPLAIN`, on an **eleven-node** table,
with planning single-threaded. The cause is upstream, duckdb/duckdb#26036. This
is known and deferred, not fixed, and it is the main reason a selector query
may feel unresponsive on this release.

**116 documented examples read an unbounded tree** (#055). Examples using
`read_ast('**/*.*')` and similar patterns match whatever the reader's working
directory holds. Measured in this repository, `**/*.*` matches 425,552 files and
33.7 GB, and running the documentation OOM-killed a 125 GB host — 96 GB
resident in one process. The engine has no cap, so it does not degrade, it
takes the machine down. Until those examples are bounded, treat any `**` glob
in the docs as a pattern to narrow before running, and prefer a path under
`test/data/`.

**Call-graph pseudo-classes can exhaust memory** (#164), on a table of about
78k nodes, killing the process rather than raising.

**The conformance kit runs nowhere in CI.** It is referenced once, in a comment.
Its controls gate takes about 110 s and the baseline emitter under 2 minutes,
while the full matrix takes about 54 minutes. Adding it is a CI-minutes
decision that has not been made.

## Upgrading

1. **Install DuckDB 2.0.** v1.5.6 is no longer built or supported. A 1.5-built
   extension and a 2.0-built one cannot co-load.
2. **If you read `ast_type_map()` by column position**, add one to every index
   from `flags` onward, or name your columns.
3. **If you read `signature_type` for Python annotated assignments**, values
   change — from a right-hand-side inference, or from the literal string
   `assignment`, to the declared annotation.
4. **If you read `parameters` for Swift calls**, a call with labelled arguments
   now yields one entry per argument instead of one entry holding all of them.
5. **If you read `is_exported(flags)` for Lua**, `local` declarations now
   report false. Code that treated every Lua declaration as exported will see
   fewer exported definitions.

## Verification

Measured on the release candidate, not carried over from the branch runs.

- Test suite, `make test_release`: `All tests passed (5 skipped tests, 9101
  assertions in 167 test cases)`. The 5 skips are the runtime-grammar files
  that need `SITTING_DUCK_TEST_GRAMMAR_DIR`; 167 ran and 172 `.test` files
  exist. v1.17.0's shipping legs reported 9027 assertions in 162 cases, so this
  is +5 files and +74 assertions.
- Module ABI gate: `OK`, 17 strategies (11 dispatched, 6 reserved), 20 traits
  mappings over 28 per-language adapters, 330 non-NONE declarations in 28
  languages, 85 `(language, strategy)` pairs.
- Native dispatch gate: `OK`, **69 known-dead literals of 1380** across 27
  languages, exactly as `spec/abi/module-abi.yaml` records them, and no new
  ones.
- `DEF_TYPE` table gate: `OK`, 3837 entries across 31 translation-unit roots,
  every entry closing on its own line, no raw type declared twice in one
  translation unit.
- Layout invariance gate: `OK`, 28 language modules each declaring exactly their
  own language, all 28 resolving at the spec's paths, 4039 `DEF_TYPE` entries
  across 58 files.
- Conformance kit, full matrix, 52m38s on a clean tree: exit 0, `TOTALS ok=194
  FAIL=0 dirty=1 void=5 UNDECL=5 n/a=19`, 28 of 28 languages with no language
  lacking a fixture, over 69 fixtures. `declared pairs: 99 in 20 languages |
  baselined as known: 14`. The matrix is 224 cells, 194 of them `ok`.
- Kit negative controls: `CONTROLS OK: every check demonstrably detects its
  planted fault`, all 10 firing. That includes the two added this cycle —
  `NATIVE-DECL`, which plants a declaration nothing can serve, and
  `NATIVE-DECL-BASE`, which plants a baseline entry that no longer reproduces
  and asserts the staleness message rather than only the verdict. Exit 0 is
  itself the controls gate; the kit uses distinct exit codes per verdict.

Scope of those two measurements, stated precisely: the suite ran at `35b4cd5`
and the kit at `751973d`, both on a clean tree. Every commit after `35b4cd5` is
documentation or a comment, with no behaviour change, so neither measurement is
carried across a code change.

What the matrix does **not** show is worth naming. The four value fixes above
changed no cell: each was at a cell the matrix already called `ok`, because the
matrix asks whether a declared pair delivers anything, not whether what it
delivers is right. The four bug tests, not the matrix, are what hold those
values.
