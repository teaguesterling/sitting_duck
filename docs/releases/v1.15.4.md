# Sitting Duck v1.15.4

**Release date:** 2026-10-03

A bugfix release. Three selector bugs shared one shape: a selector that was
wrong parsed, executed, and returned a plausible-looking answer, so nothing
told you it was wrong. Each now raises.

## Fixes

- **Zero-arity pseudo-classes reject arguments** (#184). `.fn:typed(None)`
  and `.fn:decorated(by="property")` parsed, ran, and returned the same rows
  as bare `:typed` / `:decorated` — the argument was structurally unreachable,
  so a deliberately nonsense argument behaved exactly like a plausible one.
  Both now raise and name the attribute form that actually filters
  (`[signature="None"]`, `[annotation*="property"]`). Covers all 23 zero-arity
  pseudo-classes, not just the two reported.

- **`:scope` is retired as a pseudo-class** (#184). It was ambiguous between
  three genuinely different operations, and a selector's author could not tell
  which they were getting. Each now has its own spelling:

  | Selector | Kind | What it does |
  |---|---|---|
  | `::scope` | map | replaces each match with its enclosing scope |
  | `:is-scope(…)` | filter | keeps matches that **are** a scope boundary |
  | `:in-scope(…)` | filter | keeps matches **contained within** a scope |

  `:scope`, bare or with an argument, raises an error naming all three.
  `:is-scope` is the old `:scope` behaviour under a name that says "filter" —
  `is-` matches the existing `:is-called` / `:is-referenced` convention — and
  it keeps every argument form, including the two the keyword form cannot
  express (`:is-scope(function_definition)`, `:is-scope(.fn#greet)`).

- **`#name` works on every scope argument form.** `:is-scope(.fn#foo)` worked
  while `:is-scope(function#foo)` was rejected, because the CSS grammar has no
  `.` to break `function#foo` and hands it over as a single token. That was a
  tokenizer artifact rather than a design decision; the token is now split, so
  the keyword, semantic-class and bare-tree-sitter-type forms all accept
  `#name` and agree. Malformed shapes (more than one `#`, or an empty side)
  still raise.

## Not a bug

`.call:is-scope(function)` returns no rows, because a call is not a function
scope. A well-formed selector that matches nothing returns nothing — as in
CSS, where `p.nonexistent` is an empty result rather than an error. Only
malformed selectors raise.

## Known issue

`module` scope nodes carry `name = ''` rather than a name, so
`:is-scope(module#x)` parses and filters correctly but can never match
(#186). Unaffected for `function` and `class`.

## Upgrading

Replace `:scope` with `:is-scope` (same behaviour, same arguments) or with
`::scope` if you wanted the enclosing scope. Replace `:typed(X)` with
`[signature="X"]` and `:decorated(by="X")` with `[annotation*="X"]`.
