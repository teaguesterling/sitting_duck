# v1.18.3 — names that do not bind, or bind to the wrong thing

**Status:** Approved and in progress. Done: #273, #277, #140a, #140b, #140c, #283.
Remaining: #263, then #315, then #288 with #276, then #186.
**Drafted:** 2026-11-06. **Last amended:** 2026-11-07, to admit #315.
**Scope decision:** names in v1.18.3, type misclassification in v1.18.4.
`#223`, `#255` and `#136` are deferred as features; `#260` is a breaking return-type
change and belongs to v1.19.0.

## Why these nine issues are one release

Nine open issues share one symptom: a name that a user can see in the source does
not come back from `ast_definitions()`, or comes back wrong. They do **not** share
one cause. Measured on Go at `55100c5`, there are three distinct shapes, and a
single fix closes only one of them.

| Shape | Example | `name` carried by | NAME_ROLE | `semantic_type` | in `ast_definitions()` |
|---|---|---|---|---|---|
| works | `var y int = 2` | `var_spec` | DEFINITION | `DEFINITION_VARIABLE` | yes |
| **A — invisible to the macro** (#288) | Python `for zz in items` | `identifier` | DEFINITION | `NAME_IDENTIFIER` | no |
| **B — nothing bound it** (#277) | Go `x := 1` | `identifier` | none | `NAME_IDENTIFIER` | no |
| **C — wrapper is not a definition** (#140) | Go `type Point struct` | `type_spec` | none | `EXECUTION_DECLARATION` | no |

Shape A is a macro predicate. Shape B is a missing extraction. Shape C is a
misclassified node. In shape C the inner `type_identifier Point` reads
`TYPE_REFERENCE`, so Go's struct name is currently a *reference to itself*.

A fourth shape is worse than all three, because it answers rather than omits:

| Shape | Example | `name` | correct |
|---|---|---|---|
| **D — wrong name** (#273) | `self.db = conn` | `conn` (the right-hand side) | no |

#273's own words: "A wrong definition is worse than a missing one: a
scope-resolution query gets a false binder rather than no answer."

## The sequencing constraint that drives the plan

**#288 and #276 pull in opposite directions on the same output.**

- #288: hook-bound names are **absent** from `ast_definitions()`, so the fix
  **adds** rows.
- #276: container and declarator nodes both carry NAME_DEFINITION, so
  `ast_definitions()` already returns a name **two or three times**; the fix
  **removes** rows.

Fixing #288 alone multiplies the duplicates #276 reports. Fixing #276 alone
hides how many names #288 would add. Both change every count any test asserts
over `ast_definitions()`. So they are one coordinated change with one
test-accounting pass, and they go **last**, after the per-adapter bindings have
stopped moving.

The per-adapter fixes do not need #288 first. #277's fix puts a name on
`short_var_declaration`, which already carries `DEFINITION_VARIABLE`, so it
becomes visible immediately.

## Order of work

Each numbered item is a test commit verified red, then an implementation commit.
The Golden Rule holds throughout: implementation or tests, never both at once.

**0. Survey, no code.** Re-measure all nine against the current build and record
current-versus-expected per binding site. #64 is the checklist for this step, not
a deliverable — see "Two decisions" below.

**1. #273 — the wrong name.** Independent of the macro. An `assignment` whose
target is not a bare identifier must stop reporting the right-hand side as a
definition. Python and Ruby both show it. The honest fix may be to bind nothing
where the target is not a name, which turns shape D into shape B — a smaller
defect, and one already covered by this release's other work.

**2. Per-adapter extraction, one commit pair each.** These are isolated and
independently verifiable:
  - **#277** Go `short_var_declaration`. `FIND_IDENTIFIER` returns the first
    `identifier` child, but tree-sitter-go puts `left` in an `expression_list`,
    so it finds nothing. Needs a strategy that descends the list — and `a, b := 1, 2`
    binds two names, which `name` (a single column) cannot hold. That case must
    be stated, not silently half-fixed.
  - **#140a** Bash command words. 22 of 95 `command` nodes are named.
  - **#140b** Go `struct_type` / `interface_type` names on `type_spec`.
  - **#140c** Java import names are the whole statement text, including
    `import ` and the semicolon. Python already returns clean module paths, so
    Python is the reference shape.
  - **#283** C++ variadic parameters: the three qualified forms
    (`const Args&...`, `Args&&...`, `Args*...`). The pointered form produces no
    `function_definition` row at all, which is the most serious of the three.
  - **#263** Kotlin `primary_constructor` declares native strategy `NONE`. This
    is a declared gap, so the conformance kit passes it correctly. Changing it
    means changing the declaration and the extractor together, and the kit's
    `NATIVE-DECL` line for Kotlin will move from 2/6 to 6/6.
  - **#315** C++ default arguments. **Added to the release on 2026-11-07**, after
    it was found while landing #283 — see "The tenth fix" below.

**3. #288 + #276 together.** One test-accounting pass over everything that
asserts `ast_definitions()` counts. The change is in
`src/sql_macros/tree_navigation.sql`, the `defs` CTE: `is_definition()` reads
`semantic_type` and never reads NAME_ROLE, while the walker's upgrade at
`unified_ast_backend_impl.hpp:632` writes `universal_flags` only.

**4. #186 — module names.** Blocked on a naming decision, below.

## Two decisions needed

**#64's fate.** It is an audit across 27 `.def` files, not a defect. Its
"likely missing" list is now covered by specific issues: bare parameters by
#288, for-loop targets by #288, Go declarations by #277, `variable_declarator`
by #276, field declarations by #276. Either it becomes step 0's checklist and is
closed as superseded, or it stays open as a standing audit. It should not be
counted as a tenth fix. **The tenth fix turned out to be #315**, found by
measuring rather than by auditing — which is the argument for step 0 being a
measurement pass and not a document review.

**What a module's name is.** #186 reports every `module` node with `name = ''`
— 19 of 19 in `test/data/python/*.py`, consistently empty and never NULL. So
`:is-scope(module#x)` parses, runs, and can never match. The issue itself leaves
the choice open: the basename without extension (`unicode` for `unicode.py`), or
the dotted import path where a project root can be derived (`pkg.sub.unicode`).
The basename is local and always available; the dotted path needs a root and is
wrong when there is none. This needs a deliberate answer, because it is the
value that every module-scope query will match on afterwards.

## The tenth fix: #315, admitted on 2026-11-07

Found while measuring #283, not by reading the issue list. A C++ function with a
default argument drops **every defaulted parameter** from its `parameters` list,
so the arity is short but plausible:

| source | reports | actual |
|---|---|---|
| `void m1(int a, int b = 2)` | 1 | 2 |
| `void m2(int a, int b, int c = 3)` | 2 | 3 |
| `void m3(const std::string& s, bool flag = true, int n = 0)` | 1 | 3 |

That is shape D's failure mode, not shape B's: it answers rather than omits, and
#273's own words apply — "a wrong definition is worse than a missing one". A
caller cannot tell a short list from a complete one.

**Why v1.18.3 and not v1.19.0.** Teague's instruction was to admit it unless it
belonged to v1.19.0. It does not, on four measured grounds:

1. It is this release's own subject. The cause is a dispatch arm naming
   `default_parameter_declaration`, which no grammar emits, while the real node
   is `optional_parameter_declaration` (`grammar.js:455`). That is the #220
   shape for the fourth time in this release's lineage.
2. `languages/cpp/cpp_types.def:196` already declares the node and the AST row
   already carries the name, so there is **no `.def` change** — none of the
   three CI gate classes in the survey is engaged.
3. The fix is one dispatch arm plus excising the `default_value` field in the
   helper #283 added, in the same function. No schema change, no taxonomy move,
   no breaking return type.
4. It needs **nothing from #255**. `is_optional` and `default_value` are set and
   stay invisible to SQL, exactly as `is_variadic` does after #283. Were the
   schema change required, v1.19.0 would have been right.

**Where it goes in the order:** after #263 and before #288+#276. It is
independent of #263 — different language, different file — so the order between
those two is free, and #263 keeps its approved slot. It must come before step 3,
because adding parameters moves counts and step 3 is the test-accounting pass.

**Its blast radius is real but narrow.** 67 `optional_parameter_declaration`
nodes across 15 files in our own tree, so any pin asserting a C++ parameter
count over one of those files moves. That is the same shape as #283's blast
radius and smaller, because it moves counts rather than strings.

Two siblings were filed at the same time and are **not** in this release:
**#316** (C++ lambdas report zero parameters, cause not established) and
**#317** (C and C++ return different parameter types for identical source).
Neither is a name-binding defect, and #317 wants a shared-helper decision across
two adapters.

## Risks

- **Test-count churn.** Step 3 moves counts in any file asserting
  `ast_definitions()`. Several fixtures glob `test/data/**`, so adding a probe
  file also moves unrelated counts — bug 055's unbounded-glob problem. New
  fixtures go outside the globbed trees, as `test/data/callgraph/` already does.
- **A fix that only half-lands.** #288's own report shows this already happened:
  #274 and #279 are closed but "half-closed in practice", because a role flag
  reaches scope resolution and not the macro most queries use. Every item here
  needs its assertion written against `ast_definitions()`, not only against
  `is_name_definition(flags)`.
- **One name column, two names.** Go `a, b := 1, 2` and JS `let a = 1, b = 2`
  both bind two names on one container. #276 calls the JS case "the sharpest":
  the container claims the single name `a`. No single-valued `name` column can
  be right here, so the plan must say what it does instead of picking one.
- **Suite cost.** A full local run is about 2.4 hours and prints its only count
  at the end. CI's coverage leg runs the same 173 cases in about 27 minutes, so
  CI is the cheaper gate for a count.
